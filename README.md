# מערכת ניהול ציוד – מגמת קולנוע רביבים

מערכת לניהול השאלת ציוד: תלמידים שולחים בקשה מהאתר, המערכת בודקת
זמינות אוטומטית לפי תאריכים, מנהל מאשר/דוחה, והציוד "המושאל בפועל"
נשמר אוטומטית ב-`data/bookings.json`.

הכל רץ בחינם על GitHub Pages + GitHub Actions, בלי שרת חיצוני.

## איך זה עובד (בקצרה)

- **`index.html`** — טופס עבור תלמידים. כניסה עם שם + קוד אישי
  (נשמר בדפדפן כדי לזכור אתכם בפעם הבאה), טופס בקשה עם בדיקת זמינות
  לפי תאריכים, ו"הבקשות שלי" עם סטטוס חי.
- כל בקשה נשלחת כ-**GitHub Issue** חדש עם תווית `pending`.
- Action בשם `new-request.yml` מגיב מיד עם בדיקת זמינות אוטומטית
  (תגובה על ה-issue, למידע בלבד).
- **`admin.html`** — פאנל מנהל מוגן בסיסמה. בראש העמוד לוח בקרה
  (כמה בקשות ממתינות, כמה ציוד בחוץ, כמה באיחור) ויומן איסופים/החזרות
  כרונולוגי. מתחתיו: בקשות ממתינות (לאשר/לדחות), ציוד שיצא (לסמן
  כהוחזר), אזהרות וסנקציות לפי התקנון, ועורך מלאי.
- כשהמנהל מאשר/דוחה/מסמן החזרה, זה מוסיף תווית ל-issue
  (`approved`/`rejected`/`returned`). Action בשם `on-label.yml` בודק
  שהפעולה באמת בוצעה על ידי משתמש גיטהאב מהרשימה המורשית, ומעדכן את
  `data/bookings.json` בהתאם (זו הטבלה שממנה מחושבת הזמינות בטופס).

## הגדרה ראשונית — שלב אחר שלב

### 1. יצירת הריפו וההעלאה
צור ריפו **ציבורי** בגיטהאב (Pages בחינם דורש ריפו ציבורי), והעלה
לתוכו את כל הקבצים האלה.

### 2. עריכת `config.js`
מלא את `GITHUB_OWNER` ו-`GITHUB_REPO` לפי כתובת הריפו.

### 3. יצירת טוקן "בוט" ציבורי (לשליחת בקשות מהאתר)
ב-github.com: **Settings → Developer settings → Fine-grained tokens →
Generate new token**.
- Repository access: **Only select repositories** ← בחר את הריפו הזה בלבד.
- Repository permissions: **Issues: Read and write** בלבד. שום הרשאה אחרת.
- העתק את הטוקן לתוך `GITHUB_BOT_TOKEN` ב-`config.js`.

⚠️ **חשוב להבין:** טוקן זה גלוי בקוד המקור של האתר לכל מי שרואה אותו
(זו מגבלה בסיסית של אתר בלי שרת). לכן חובה להגביל אותו **רק** ל-Issues
של הריפו הזה. במקרה הגרוע ביותר מישהו יוכל ליצור/להעיר על issues, אבל
לא לגעת בקוד, בקבצים, או במלאי — וגם לא "לאשר" בקשות בעצמו, כי לכך יש
הגנה נפרדת (סעיף 5).

### 4. יצירת התוויות (Labels) בריפו
ב-Settings → Labels, צור: `pending`, `approved`, `rejected`, `returned`,
`picked_up`.

### 5. רשימת מנהלים מורשים
Settings → Secrets and variables → Actions → **Variables** → New
repository variable:
- שם: `ADMIN_GITHUB_LOGINS`
- ערך: שם המשתמש שלך בגיטהאב (אם כמה מנהלים — מופרדים בפסיקים, למשל
  `michael123,teacher456`)

זו ההגנה המרכזית: רק פעולות תיוג שמגיעות ממשתמש ברשימה הזו ייחשבו
תקפות. פעולה מכל משתמש אחר (כולל אם טוקן הבוט "יזלוג") תבוטל אוטומטית.

### 6. הרשאות כתיבה ל-Actions
Settings → Actions → General → Workflow permissions → בחר
**"Read and write permissions"** ושמור. (אחרת ה-Actions לא יוכלו לעדכן
את `data/bookings.json`.)

### 7. הפעלת GitHub Pages
Settings → Pages → Source: **Deploy from a branch** → Branch: `main`,
תיקייה `/ (root)`.

### 8. רשימת תלמידים
ערוך את `data/students.json` — הוסף שם, כיתה, וקוד אישי לכל תלמיד.

⚠️ **אל תשתמש במספרי תעודת זהות אמיתיים כאן.** הקובץ הזה ציבורי (חלק
מריפו ציבורי), וגם אם היה מוצפן/מגובב — למספר ת"ז יש מעט מדי אפשרויות
כדי שזה יהיה הגנה אמיתית. במקום זה בחר קוד שרירותי לכל תלמיד (למשל 4
ספרות) ותן להם אותו בעל פה או בהודעה פרטית.

### 9. תקנון והתחייבות תלמיד ("חתימה")
ב-`config.js` יש `RULES_DOC_URL` שמצביע על מסמך התקנון. **חובה** לפתוח
אותו לצפייה: Google Docs → Share → "Anyone with the link" → Viewer —
אחרת התלמידים לא יוכלו לקרוא את מה שהם מאשרים.

בכל שליחת בקשה התלמיד/ה חייב/ת לסמן ✔ שקרא/ה את התקנון — זה נשמר
לצמיתות בתוך ה-issue (שם, שעה מדויקת). בנוסף, כשהבקשה מאושרת, בעמוד
"הבקשות שלי" מופיע כפתור **"אישור איסוף בפועל"** שהתלמיד/ה לוחצ/ת עליו
כשהוא/היא בפועל בא/ה לקחת את הציוד — גם זה נרשם כתגובה על ה-issue עם
שם ושעה, כמעין "חתימה" שנייה.

### 9א. אזהרות וסנקציות
בפאנל הניהול יש עכשיו קטע **"אזהרות וסנקציות"**: בוחרים תלמיד/ה,
סוג (אזהרה / השעיה, עם תאריך סיום אופציונלי להשעיה) וסיבה — נשמר
ב-`data/sanctions.json`. תלמיד/ה עם השעיה פעילה לא יוכל/תוכל לשלוח
בקשה חדשה (האתר חוסם ומציג הודעה), ואזהרות מוצגות לתלמיד/ה בעמוד
"הבקשות שלי". בבקשות הממתינות לאישור, המנהל רואה אם לתלמיד/ה יש
היסטוריית אזהרות.

⚠️ הסוגים והסיבות הם כרגע כלליים — לא הצלחתי לקרוא את התוכן המלא של
מסמך התקנון (הקישור ששותף דורש הרשאת גישה). אם רוצים שרשימת הסיבות
תואמת בדיוק לקטגוריות ההפרה שמוגדרות שם, יש לשתף את תוכן המסמך.

### 10. מלאי ציוד
ערוך את `data/inventory.json` (או פשוט דרך `admin.html` אחרי שהוא
עובד) — הכמויות שם כרגע הן ערכי דוגמה בלבד.

### 11. יצירת סיסמת המנהל
1. צור טוקן נוסף (**נפרד מטוקן הבוט**), עם הרשאות **Issues: Read and
   write** וגם **Contents: Read and write**, מוגבל לריפו הזה בלבד.
2. היכנס לעמוד `setup.html` באתר (אחרי שהוא כבר עלה, או פתח את הקובץ
   מקומית בדפדפן), הדבק את הטוקן, בחר סיסמה, ולחץ "צור קובץ הצפנה".
3. שמור את הפלט כקובץ `data/admin-secret.json` והעלה אותו לריפו
   (זהו ciphertext בלבד — בלי הסיסמה אי אפשר לחלץ ממנו את הטוקן).
4. מעכשיו הכניסה ל-`admin.html` היא עם הסיסמה שבחרת.

### 12. בדיקה
מלא בקשה מ-`index.html`, ולך לבדוק שה-issue נוצר, שההערה האוטומטית
של בדיקת הזמינות הופיעה, שאישור/דחייה מ-`admin.html` עובד, ושסימון
"הוחזר" מוריד את הפריט מ-`data/bookings.json`.

## מגבלות ידועות

- טוקן הבוט הציבורי חשוף בקוד — מוגבל בכוונה ל-Issues בלבד כדי לצמצם
  נזק אפשרי.
- סיסמת המנהל וקוד התלמיד הם הגנה סבירה לגודל של מגמה בבית ספר, לא
  רמת אבטחה ארגונית. אל תשתמשו במידע רגיש אמיתי (ת"ז, סיסמאות
  שמשמשות במקומות אחרים וכו').
- GitHub Pages דורש ריפו ציבורי לתוכנית החינמית — כל תוכן בריפו (כולל
  `data/students.json` עם השמות) גלוי לציבור.
